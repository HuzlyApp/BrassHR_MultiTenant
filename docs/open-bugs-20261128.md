# Open bug fixes - 28 November 2026

Started from staging 35361ef8 after pulling. Bug Log tester statuses: 71 Open, 13 Reopened, 7 In Progress (91 unresolved), plus 7 Blocked. Fixed/Verified rows were excluded. QA results and historical remarks are not changed by developer implementation status.

## Implementation completed; signed-in QA pending

- BUG-398, BUG-399: preserve typed pay input and reject ranges, negatives, zero, letters, exponents and extra decimals in the editor and both profile API normalization paths. The same agreed-rate validator serves both sides. Valid single rates retain cents and their hourly/weekly/monthly period. No historical pay value was reconstructed or changed, and no arbitrary business maximum was invented.
- BUG-383: reject short/malformed ZIPs rather than padding them. Preserve valid leading zeros and normalize valid nine-digit ZIP+4 consistently on client/API.
- BUG-400: preserve invalid DOB input for a meaningful format error; reject impossible/future dates on client and server, including ISO calendar overflows. Supported US/ISO dates remain accepted.
- BUG-381: Add Applicant validates phone format/length before enabling submission and again at the API. US and explicit international country-code numbers remain supported there. Public apply retains typed overlong/invalid input and rejects it instead of truncating to ten digits; that form retains its existing US-only contract.
- BUG-382: Add Applicant and public apply reject one-letter TLDs, preserving valid subdomains, plus-addressing and punycode TLDs. Shared public validation also runs in save-worker.
- BUG-384: job-title field preserves the typed text, shows a 200-character counter and keeps the existing form/API length validation.
- BUG-394: client edit validates locally before mutation and retains API errors; whitespace-only and HTML names are rejected visibly.
- BUG-395: facility create/edit use the existing client-name validation policy (plain text, 2-120 characters), with visible guidance and server enforcement.
- BUG-396: facility edit clears stale mutation errors on correction; API/service checks reject short/malformed phone numbers. Business phone validation checks the full input rather than a silently truncated digit string.
- BUG-397: successful client archive/restore/edit shows explicit success feedback after the mutation.
- BUG-419: public name fields preserve over-limit text and show the existing 50-character limit and a specific error instead of silently dropping text.

## Partial or still open

- BUG-421: public first/last name fields now reject markup with inline errors and shared API validation; international names retain existing shared person-name rules. The separate candidate-portal Preferred Name case from the latest QA remark is not covered, so the bug remains In Progress.
- BUG-380: reviewed the idle/session code. Idle timeout is two hours, the client activity cookie expires after three hours, and a missing activity timestamp bootstraps anew. A separate signed staff proof has a 12-hour absolute expiry. This explains why an idle session can resume before that proof expires; durable server-enforced activity/revocation remains open. No weaker authentication bypass or cookie-only patch is presented as a fix.
- BUG-306: reviewed bootstrap and restart behavior. The prior-applicant banner checks storage after bootstrap has already created an applicant ID, so a fresh applicant can receive the misleading banner. The stricter later-interaction sign-in rule requires server-side identity/session changes; it is not fixed by hiding the banner. The bug remains open for that work.
- BUG-405/418: the new 5 MB resume product requirement needs one consistent per-file boundary and a direct-upload path for larger files. No upload fix is claimed in this batch.
